# 概念圖對齊（align）

目標：遊戲畫面以 `assets/title.png`（概念圖）為基準。這頁記錄「怎麼量」與「把概念圖變成遊戲資料」的做法。

## 量測

```sh
npm run build
node pipeline/scripts/align/capture.mjs out.png          # art-complete 模式、1000×1000、同概念圖構圖（大廳寬 35%），只拍 canvas
python pipeline/scripts/align/metrics.py out.png --side side.png
```

`metrics.py`：兩張縮 500×500 比 —— `hist_bc`／`hist_inter`（RGB 直方圖，1＝相同）、`lum`／`sat`、色群比例
（暗、石、綠、土、紅、青、藍、紫）、`detail`（Laplacian）、`conform`／`pal_de`（概念圖 48 色票）。
概念圖自己：conform 0.936、pal_de 17.1（這是天花板，不是 1.0）。

全地圖仍用 `l0veyou/verify_all_regions.js`（8 區 × 3 縮放）；**前後比較要同條件**（同視窗、同版本跑法），
文件裡舊數字在 1440×900 下重現不了。

而且遊戲有 UI、名牌、可移動的鏡頭與建築。剩下的差主要是「土色比例偏高、暗部偏少」——概念圖地面上壓滿角色與道具。

## 概念圖 → 遊戲資料

概念圖 ↔ 世界：紀念碑 (-8,2) ↔ 概念圖 (640,613.6)，K = 3.93 px/世界單位（大廳 440px＝112），等角 9:4.5。
概念圖畫框＝x−z∈[−28.1,7.36]、x+z∈[−40.7,30.2]。

| 檔案 | 產生方式 | 內容 |
|---|---|---|
| `src/concept-ground.js` | `python pipeline/scripts/align/concept_ground.py` | 每 0.5 格的地面類（石板/土路/草）＋概念圖樹冠上的樹 |
| `assets/concept-{stone,earth,grass}.png` | `python pipeline/scripts/align/concept_textures.py` | 用概念圖像素做環繞式 image quilting 的無縫材質（360px，原生 3.93 px/單位）；土路色調配到概念圖整體土色 |
| `src/concept-props.js` | 手量概念圖像素 | 道具、圍籬、角色的位置（存概念圖座標，執行時換算） |
| `assets/concept-clean/*-v3.png` | l0veyou 參考圖 → `make_building.py` | 鐵匠鋪、學院、酒館、獵人小屋、餐廳、交易所 |
| `assets/hero@1x/@2x` | l0veyou 參考圖 → `make_heroes.py` | 六職業 Q 版冒險者 |

- **村莊高解析地面層**（`pixel-world.js` `buildVillageLayer`）：大地面畫布只有 GROUND_RES（桌機 2 px/單位），
  概念圖畫框另畫一張 VRES＝2×GROUND_RES 的地面，材質 1:1；溪流、橋、戰鬥空地不蓋。
- 畫框內程序撒的樹與家具會先清掉，再放概念圖的（結構物：柵欄、閘門、橋欄、紀念碑不動）。
- 預設建築位置照概念圖量；舊預設在 `ART_LAYOUT_HISTORY`，存檔還是舊預設就自動搬到新預設。
- `SPRITE_SHIFT`：只移動圖、不動佔地（酒館連露台往右下畫），避免改到道路測試。

## l0veyou 參考圖做法（建築、角色）

1. 從概念圖裁出該建築（含一點周邊）→ `output/l0veyou/ref/<id>-ref.png`。
2. 站上「添加参考图」上傳（瀏覽器自動化：`input.file-input` 設檔），prompt 要求「只畫參考圖裡的某棟、補完被切掉的部分、洋紅底」。
   注意：上傳的參考圖本身也會出現在頁面上，抓結果時要排除 `data:` 網址。
3. `make_building.py`（碰邊檢查、裁切）→ 縮到跟 v2 同解析度，`build.mjs` 優先用 v3。
4. **紫色主體要關影子規則**：`NO_SHADOW=1 NO_HOLES=1 HUE_TOL=12`，不然紫屋頂會被當成洋紅影子吃掉（酒館、學院踩過）。
