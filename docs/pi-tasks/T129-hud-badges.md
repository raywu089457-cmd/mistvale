# T129 HUD 待處理徽章

Status: done
Type: ui
Accept: `node tools/checks/hud-badges.mjs && npm run verify:quick`

## Goal

底部分頁（建設／獵人／交易／製作／地下城／競技場／委託）完全沒有狀態提示：委託做完了不知道、
有買得起的旅人可以招募也不知道、還有空地可以蓋新房子也看不出來。玩家只能靠逐一打開面板找。

這輪在按鈕右上角加**數字徽章**：

| 按鈕 | 條件 | 文案（aria-label） |
| --- | --- | --- |
| 委託 | 本章獎勵可領取 | `委託：1 件獎勵可領取` |
| 獵人 | 有買得起的訪客 | `獵人：N 位訪客可招募` |
| 建設 | 有「還沒蓋且買得起」的建築 | `建設：N 棟可升級` |

- 徽章用 CSS `::after` + `data-badge`，**不改 DOM、不佔版面**（按鈕尺寸完全不變，不會推擠列）。
- `prefers-reduced-motion` 時不做彈出動畫；手機徽章縮小 1px。
- 超過 9 顯示 `9+`。

## Files

- `src/pixel-ui.js`：`buildableCount()`（只算未建造且買得起、通過大廳限制的建築）、`paintBadges(s)`
  （寫 `data-badge` 與 `aria-label`），`paint()` 尾端呼叫。
- `src/pixel-style.css`：檔尾 T129 區塊（徽章外觀、`badgePop` 動畫、減少動態、手機尺寸）。
- `tools/checks/hud-badges.mjs`（新）。

## Decisions

- **只有「真的有事要做」才掛徽章**：第一版把「日常升級」與「可製作的配方」也算進去，
  結果建設永遠是 `9+`、製作永遠是 `6`——徽章一輩子亮著就等於沒有徽章。
  改成：委託待領取、有買得起的訪客、有**還沒蓋**的建築。
- **用 `::after` 而不是插入 `<em>`**：徽章不佔 layout，按鈕不會因為出現／消失而位移；
  檢查器也驗了「出現前後尺寸差 < 0.6px」。
- **數字上限 `9+`**：按鈕只有 ~78px 寬，三位數會擠出按鈕。
- **aria-label 寫完整句子**：視覺徽章對螢幕閱讀器沒有意義，所以按鈕本身補 `aria-label`；
  沒有徽章時移除（回到原本的按鈕文字）。
- **建設只算「未建造」**：已建好的日常升級太頻繁，掛在 HUD 上會變成噪音。

## Notes

- `paint()` 大約每 400ms 跑一次，所以檢查器改完 `state` 要等 ~900ms 才讀得到新徽章
  （第一版只等 300ms，讀到的是舊狀態）。
- 檢查器的建設期望值是「建設面板裡 `.building-card.unbuilt:not(.tight)` 的張數」——
  直接對照真實判斷邏輯，而不是我自己在檢查器裡重算一次成本。
- `dataset.badge` 不存在時是 `undefined`，讀取要 `|| ''`，不要用 `'(none)'` 這種哨兵字串
  （會讓「沒有徽章」的判斷全部失敗）。
- 徽章出現後點按鈕仍會正常開面板（徽章 `pointer-events:none`）。
