# T146 360 寬的入門嚮導：主要按鈕不用捲就看到

Status: done
Type: ui
Accept: `node tools/checks/welcome.mjs && npm run verify`

## Goal

目標要求手機操作順暢。量了新手入門嚮導（第一次開局那張）：360×640 時內容 597px 高、
可見區只有 401px——**「開始遊戲」要捲到底才看得到**，第一次玩的玩家很可能卡在這一步。

## Files

- `src/pixel-style.css` 檔尾 T146 區塊，全部只影響 welcome 面板：
  - `@media(max-width:480px)`：橫幅收成一列、內距與行高收緊、按鈕 44px
  - `@media(max-width:400px)`：**橫幅整塊省略**（標題已經是「獵人入門」）、
    提示區塊省略（同樣內容在「說明」面板有）、三步驟內距與行高再降一級
  - 兩顆按鈕在 ≤480 改成並排，省下一整列高度
- `tools/checks/welcome.mjs`：手機段改成 360×640（支援範圍內最窄），並新增
  「不捲動就看得到且點得到兩顆按鈕」的斷言（`scrollTop=0` 時按鈕矩形要落在
  `#modal-content` 可見區內，且中心點 `elementFromPoint` 落在按鈕上）。

## 結果

| 寬度 | 之前 | 之後 |
| --- | --- | --- |
| 360×640 | 內容 597px / 可見 401px，**開始遊戲要捲** | 內容 505px / 可見 505px，三步驟＋兩顆按鈕一次看完 |
| 402×712 | 內容 533px / 可見 464px，要捲一點 | 內容 627px / 可見 605px，全部在視窗內 |

## Decisions

- **不是把按鈕做成 sticky**：試過固定在底下，結果 360 寬時會蓋住第三步驟（文字被切一半更糟）。
  改成「真的把內容縮到一次看得完」，手機上比較乾淨。
- 360 才省略橫幅與提示：更寬的螢幕留著，資訊不犧牲。
- 三步驟的文案完全沒動，只動間距與字級。

## Notes

- 這輪試了四個版本才成（sticky 底欄 → 只收內距 → 收提示 → 平行按鈕 → 省略橫幅），
  中途的 3D 版本都是靠探針量「內容高度 vs 可見高度」判斷，不是靠眼睛看。
