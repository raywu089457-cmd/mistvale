# T149 橫向手機（矮視窗）的觸控尺寸：部分改善，橫向版面另開一輪

Status: partial（可上線的改善已進；橫向 topbar 擁擠留待專門一輪）
Type: ui
Accept: `node tools/checks/mobile-touch-44.mjs && npm run verify`

## 發現（712×402 橫向手機）

橫向時介面整體 `zoom: 0.75`（`#game-ui{zoom:var(--ui-scale)}`），所以

- 底欄 9 個分頁的按鈕實際只有 **97×33**（要 44 高）
- 底欄本身只有 36px 高
- 浮動鈕（縮放／說明）壓到最右邊的分頁
- 召喚首領的浮動鈕壓到底欄的「委託」
- topbar 六顆按鈕擠在 48px 高的一列，且 `地圖 × 暫停`、`設定 × 暫停` 互相重疊（**這是既有問題**，
  不是這輪造成）

## 這輪修的

- `--t52`（介面縮放倒數）在橫向也宣告，`#game-ui` 內的控制項用 `calc(44px * var(--t52,1))`
  → 底欄按鈕實際渲染 44px（不是 33）
- 底欄高度跟著長到 60px（`calc(60px * var(--t52,1))`），按鈕不會被 flex 壓回去
- 浮動鈕（`.view-tools`）抬高到新底欄之上，不再壓到分頁
- 召喚首領鈕同樣抬高

## 還沒修（留待專門一輪）

- **topbar 六顆按鈕在 48px 高的一列互相重疊**（地圖／暫停／速度只有 38px 寬、且與設定鈕重疊）——
  需要重新設計橫向的頂部列（例如收進「選單」或分成兩列），不是調尺寸能解決
- 因此橫向目前**不列入 44px 觸控驗收**（`tools/checks/mobile-touch-44.mjs` 仍只驗 402／360 直向）

## Decisions

- 不把 topbar 硬拉成 44px 寬：實測只會讓六顆按鈕更擠、重疊更嚴重；先保住「不重疊」優先，
  尺寸問題連同橫向版面一起處理。
- 檢查器維持直向（402／360）：橫向還沒通過自己的稽核，不能放進 Accept 假裝通過。

## Notes

- 這輪中途試過把浮動鈕搬到 topbar 下方、與地圖鈕同列，反而製造新的重疊；已回退，
  只留「抬高到新底欄之上」這種沒有副作用的改動。
- 教訓：`#game-ui` 內的尺寸要乘 `var(--t52)`（介面縮放倒數），否則 `zoom:0.75` 會把 44px 畫成 33px。
