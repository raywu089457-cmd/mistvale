Status: done

## Goal
The user wants the archer walk GENERATED BY pixelfx's own rig, yet looking 100% like the l0veyou reference `output/l0veyou/archer-idle-pixelfx-v2-1x.png` (33x52; alpha 0 = background). Approach: texture the reference onto pixelfx's 3D rig. pixelfx's renderer (`C:/Users/ray/pixelfx/src/core/rig.js`: `posed(pose)` returns per-pixel `src` = the rest-pose pixel each posed pixel came from; see also `posedParts`, `skeleton`) produces every frame's geometry; each output pixel's colour is the reference pixel at that pixel's rest position. So frame 0 / idle (rest pose) must equal the reference pixel-for-pixel, and every walk pixel is an exact reference colour.
- Problems the plan must solve: the rig's rest body is 24x38 (`W0/H0`, measurements `M`) but the reference is 33x52, so the rest skeleton must be fitted/scaled to the reference (a vendored, scaled copy of rig.js under `pipeline/scripts/pixelfx/vendor/` is allowed; never edit pixelfx's own `src/core/`); reference pixels outside the rig silhouette (cloak, hair, bow) must be bound to a bone (e.g. nearest bone / explicit regions) so pixelfx's transforms move them too; holes and overlaps after posing must be resolved without inventing colours (nearest-source fill is fine).
- Output a NEW move `moves/archer-walk-rig-tex`: 1 idle frame + 8-frame walk loop at 8 fps, with a clear stride (contact-frame feet >= 6 px apart). Files: `assets/vfx-sheets/archer-walk-rig-tex.{png,json}`, `output/pixelfx-archer-walk-rig-tex/compare.png` (6x: reference | idle frame | walk frame 2 | walk frame 6), `frames-6x.png`, `walk.gif`, `strip.png` (8 walk frames 1x, equal cells; print cell w/h). Leave `archer-walk`, `archer-walk-l0v` untouched.
- New checker `tools/checks/archer-walk-rig-tex.mjs`, failing if: idle frame != reference (all pixels, alpha included); any walk pixel's colour is not exactly a reference colour; sheet lacks 1+8 frames; contact feet < 6 px apart; any leg is not one 4-connected shape; two consecutive walk frames are identical; or the frame geometry is not produced by the rig (the move/export must call the rig's posing per frame — no hand-cut parts atlas, no per-part whole-pixel offsets like T76).
- No change to src/.
