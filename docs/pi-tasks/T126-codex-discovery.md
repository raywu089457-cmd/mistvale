# T126 圖鑑的「探索」狀態：未遇見剪影＋擊殺次數

Status: done
Type: ui + game-state
Accept: `node tools/checks/codex.mjs && npm run verify:quick`

## Goal

T125 的圖鑑從一開始就把 22 種魔物的名字、數值、掉落全部寫出來——沒有「還沒見過」的空間，
也沒有理由特地去找某隻魔物。這輪讓圖鑑有探索感：

1. **沒打過 = 剪影＋？？？**：頭像只留暗輪廓、名字問號、四項數值都是 `?`、掉落寫「還沒記錄掉落」、
   描述寫「擊殺一隻後才會記錄。」（首領也一樣）。
2. **打過才揭露**，並在名字旁邊顯示累計擊殺次數 `×N`。
3. 摘要改成 `已記錄 3／22 種 · 累計擊殺 6 次 · 7 個區域`。
4. 擊殺次數寫進存檔（新欄位 `state.codex`），舊存檔讀進來時自動補空物件，不會壞。

## Files

- `src/pixel-game.js`：新存檔欄位 `codex: {}`；`rewardEnemy()`（獵人擊殺）與 `wandererLoot()`
  （流浪英雄擊殺）兩條路徑都 `state.codex[enemy.type] = (state.codex[enemy.type] || 0) + 1`；
  讀檔正規化只保留「正整數且 ENEMIES 有的 key」。
- `src/pixel-ui.js`：圖鑑卡片改為 `unknown` / `seen` 兩態（含首領），摘要改寫。
- `src/pixel-style.css`：T126 區塊（問號卡配色、剪影濾鏡、`.cx-kill` 次數徽章）。
- `tools/checks/codex.mjs`：改寫成三階段驗證（全未知 → 部分揭露 → 全部揭露比對資料）＋原始碼檢查。

## Decisions

- **統計放在遊戲層（state）而不是 UI**：擊殺次數要跟存檔一起走；只放在畫面會重整就消失。
- **兩條擊殺路徑都要記**：獵人出征與流浪英雄互毆都是「玩家看著牠死」，只記一邊會讓圖鑑數字對不上實際經歷。
- **剪影用 `grayscale + brightness(.42)`，不要全黑**：全黑在深色卡上會變成一個空方塊，看起來像壞圖；
  留一點輪廓才像「還沒點亮」的圖鑑。
- **未知時連數值都不揭露（顯示 `?`）**：只遮名字但露數值會洩漏「哪隻值得打」的資訊，探索感就沒了。
- **首領也走同一套**：牠是最該「第一次打過才記錄」的目標。
