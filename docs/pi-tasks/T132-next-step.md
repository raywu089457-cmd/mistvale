# T132 下一步建議條

Status: done
Type: ui / guidance
Accept: `node tools/checks/next-step.mjs && npm run verify:quick`

## Goal

遊戲玩到一半常常「不知道現在該做什麼」：委託做完了忘記領、有旅人站在村口沒招、
三個獵人待機卻沒派去地下城。以前只能靠自己逐一打開七個面板看。這輪在畫面下方加一條
**下一步建議**：從 state 推出「現在最該做的一件事」，點一下直接跳到對應面板。

優先序（高 → 低）：

| # | 條件 | 文案 | 點擊 |
| --- | --- | --- | --- |
| 1 | 委託章節獎勵可領取 | 村長委託的獎勵可以領了 | 委託 |
| 2 | 有買得起的旅人 | 有 N 位旅人願意加入 | 名冊 |
| 3 | 已建地下城、≥3 位待機、沒在跑也沒冷卻 | N 位獵人待機，可以派去地下城 | 地下城 |
| 4 | 資源夠蓋新（未建造）建築 | 資源夠了，可以蓋新的建築 | 建設 |
| 5 | 已建地下城但待機不足 3 位 | 派滿 3 位獵人就能進地下城（目前 N 位待機） | 地下城 |
| 6 | 所有獵人都在村裡待機 | 獵人都在村裡待機，可以派到生態區蒐集材料 | 地圖 |

都沒有 → 整條收起來。面板開著、單位小卡開著、建築面板（`#inspector`）開著、
正在放置建築時都不顯示。

## Files

- `src/pixel-style.css`：檔尾 T132 區塊（深色卡片、金色「查看」小標、`nsIn` 進場、減少動態、手機位置）。
- `tools/checks/next-step.mjs`（新）。

## Decisions

- **位置被按鈕巡檢逼著改了三次**（重要教訓：畫面下方其實很擠）：
  1. 置中貼底欄 → 壓到左下角的村莊日誌（canvas 文字）。
  2. 靠右下 → 蓋住右下角的 說明（?）與 召喚首領 浮動鈕。
  3. 最終：**桌機置中、抬到底欄上方 30px**（高於日誌那一帶）；**手機靠左、右側留 104px** 給
     縮放／說明／首領那一列浮動鈕，並抬到 110px 高。
- **不記「已提示過」**：條件消失就自己收起來，不需要額外的 dismissed 狀態；
  玩家做了事，提示自然換下一件事。
- **一定要有「跳過去」的按鈕文字**（查看委託／看名冊／去地下城…）：
  只寫一句話會讓人以為是公告，寫出動作才知道可以點。
- **不用 toast 系統**：toast 3 秒就消失，這條是要「一直在那裡直到你做完」。
- **順序不是隨機**：可領取的獎勵 → 免費的戰力成長（旅人）→ 地下城 → 建設；越前面越接近
  「已經付出、只差領取」或「不花錢就能變強」。
- **panel 開著就收起**：面板／inspector／單位小卡都會蓋住同一個區域，不收起就會互相重疊。

## Notes

- 檢查器逐情境驗：委託／旅人／地下城三種（文字、`data-key`、`data-act`、`aria-label`、
  點擊後開對應面板）、全員待機（提到生態區）、什麼都沒有（整條不存在）、
  面板開著要收起且關掉要回來、位置間距、桌機置中且不壓日誌、
  手機在畫面內、不擋地圖／暫停／速度／縮放／說明／首領浮動鈕、中心點是自己（沒有被別層蓋住）。
- **按鈕巡檢才抓得到這種問題**：單看自己的檢查器全綠，但 `npm run verify` 的手機巡檢
  連續兩次回報 `COVERED by next-step`（第一次是 說明／首領／inspector 三顆，第二次是縮放 −）。
  新增覆蓋畫面的浮動元件時，一定要跑完整 verify。
- 每幀只比對字串，沒有變就不碰 DOM——避免每幀重建節點。
- 這條跟 `#run-hud`（地下城／競技場進行中的小隊條）是不同情境：`#run-hud` 貼上方，
  進行中戰鬥時建議條仍可能出現（例如委託可領），兩者不衝突。
