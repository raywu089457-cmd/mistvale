# UI/UX optimization plan (2026-11-01, planned by Claude in the Opus role)

Method: follow `docs/DISPATCH-PLAYBOOK.md`. Assets come from l0veyou (free). PixelLab credits: 0. Nothing is pushed until the user says 推 or 交接.

## 1. Baseline (what I looked at)
- `npm run verify:quick` passes (2026-11-01 02:07). Layout checker: 0 FIX on the three devices in the current `output/ui-audit/layout/summary.txt`.
- I looked at screenshots `desktop-hud`, `phone-hud`, `phone-hunters`, `desktop-difficulty`, `desktop-build` in `output/ui-audit/shots/`. The UI is already consistent (wood frame, gold corners). What is left is polish and consistency, not a rebuild.

## 2. Findings (visual judgement; each is one ticket)

| # | Finding | Screen | Fix type |
|---|---|---|---|
| F1 | 8 modals have an illustrated banner (trade, quests, craft, inventory, recruit, dungeon, arena, boss). These have none: build, hunters roster, difficulty, help, settings, dispatch. Plain `modal-intro` text feels unfinished next to the others. | desktop + phone | **asset + CSS/JS** |
| F2 | Phone hunters roster: filter chips (5 rows) take about 40% of the visible modal, so the first hunter card is mostly below the fold. | phone-hunters | CSS/JS: collapse filter and sort into one row or a toggle |
| F3 | Phone map: region name labels are clipped at the screen edge (向陽草原, an unreadable 地), and a lot of the screen is ocean. | phone-hud | camera default + label clamp (game code, tier C) |
| F4 | Top bar has a lone `+` button after the resources with no label. Players cannot tell what it does. | desktop + phone | label/tooltip, or move into a menu |
| F5 | Small text: desktop `自動儲存` and the bottom hint line, difficulty-card details (about 10px), `Lv.1` captions in the build grid. | desktop | CSS only |
| F6 | Build modal: cards show no cost until scrolled/selected; first-time players cannot compare. | desktop-build | JS (small) |

F3 touches camera/rendering (`pixel-world.js`) so it stays with Claude/Opus. F1 is the main use of free assets.

## 4. Risks and limits
- l0veyou has a daily free quota. Phase A needs 6 images; if the quota ends, generate the rest on the next day (the card stops and reports, it does not switch to paid tools).
- The l0veyou browser must be logged in (checked at planning time: not asking for login).
- Image quality is a visual call: phase B is mine, not pi's.
- Do not touch `src/pixel-game.js` logic or `src/pixel-world.js` except phase E.
